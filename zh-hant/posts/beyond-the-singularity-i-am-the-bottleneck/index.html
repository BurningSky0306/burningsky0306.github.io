越過奇點之後，我是唯一的瓶頸

當前沿模型跨過個人的適應性奇點，阻礙任務推進的壁壘便從工具退回了我自己。在用不完的算力餘量面前，我不得不從一問一答的互動中心抽身，嘗試成為設計自主執行系統的那個人。

最近幾個月以來，我基本擁有了有限但對我個人而言絕對充足的 Token。如何把這些 Token 物盡其用，成了困擾我的最高優先等級問題。尤其是在半個月前把 Claude Pro 升級為 Max 之後，這種反差愈發清晰。我每天都要花大量時間去消耗額度，卻始終只能用掉一半。

很長一段時間裡，我習慣了等待更聰明的模型，習慣把停滯歸咎於工具的邊界。但自從 Opus 5.5 問世之後，在我個人能力保持緩慢提高的前提下，幾乎我所有的任務都不再因為模型的能力瓶頸而停擺。最先進的模型的發展對於我來說，已經抵達了一個「適應性奇點」。只要面對 Opus 5.5 及以上水準的模型，在我的任何任務情境下，阻礙或推遲任務往下推進的壁壘，都在我身上，而不再在模型。

為了推進某項任務，我需要花大量時間和模型反覆 grilling，制定詳細且我能夠理解的計畫，設計工作流程架構並親自測試執行。在整個任務鏈條裡，最耗時的恰恰是我參與的那部分。如果要用 Claude 的訂閱計畫來類比個人的能力，或者更準確地說，在保證每一個 Token 都儘可能發揮作用而非空轉浪費的前提下，用有效消耗的額度來丈量我對 Agent 的理解、運用和掌握程度，那麼滿負荷運轉的我頂多也只能算作 Claude Pro 2.5x，我每天傾注大量心力與它互動，也只能觸及 Max 額度的一半。倘若考慮勞逸結合因素，這個數字甚至要回落到 Claude Pro 1.7x。

回想去年下半年，談及 AI 和 Agent 發展帶給我最大的收穫，我曾歸結為觀念進步、能力提高和提供自洽框架。那時的我欣喜於陌生領域的門檻被壓縮到隨時敢去碰一碰，欣喜於隨時浮現的念頭能立刻得到回覆和延續，也受惠於它能將碎片化的知識迅速組織成自洽的圖式。但回頭再看，那三層收穫之所以讓我滿足，是因為我彼時依然站在互動的中心，本質上都是一場一場的「雙人問答」。思考終於有了高效能的即時回饋，可回饋的頻率，依然受限於我自己的體力。

當我翻閱了 Anthropic 官方更新的幾篇部落格文章之後，發現前沿研究者很早就在嘗試建構 long-running agents / always-on agents 了。那些探索照出了我停留在「Claude Pro 1.7x」的真正原因：只要我還執著於親手審閱每一個中間步驟、親自充當每一次迴圈的觸發器，我就永遠只能用肉身的線性時間去餵養指數級膨脹的算力。

我意識到，如今在提高 Agent 理解、運用和掌握能力這件事情上，最急切的已不再是打磨單次互動的技巧。我需要儘可能設計一個讓 Agent 自主執行並自我迭代的系統。在新的分工裡，我僅僅負責設計、評估和最佳化系統，而實際參與一線工作的全是 Agent 本身。從去年為思考擁有了即時回饋而雀躍，到如今在算力的餘量面前審視自身的侷限，我或許在這條道路上又往前邁得更遠了。

只是，新的問題出現了，如若讓 Agent 在沒有我的晝夜裡運轉、將曾經用不完的額度頃刻吞沒時，那個跑得比我的審視還要快的系統，又會在哪一層等著與我這位新的瓶頸重逢？
